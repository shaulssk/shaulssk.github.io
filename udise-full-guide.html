ಇದು ಸರ್ಕಾರದ ಅಧಿಕೃತ ಪುಟವಲ್ಲ — ಸ್ವತಂತ್ರ ಮಾರ್ಗದರ್ಶಿ.

📋 Official Source / ಅಧಿಕೃತ ಮೂಲ: Ministry of Education / NIEPA (UDISE+) — udiseplus.gov.in · schooleducation.karnataka.gov.in

✅ Last verified: 09 September 2026

ℹ️ Note: Portal instructions, Reference Date and menus may change — ಅಧಿಕೃತ circular/portal instructions ಬದಲಾದರೆ ಅವುಗಳೇ ಅಂತಿಮ. data submit ಮಾಡುವ ಮುನ್ನ ಇಲಾಖಾ ಪರಿಚಲನೆ/ಅಧಿಕೃತ portal ಪರಿಶೀಲಿಸಿ.

UDISE+ — ಭಾರತದ ಎಲ್ಲಾ ಮಾನ್ಯತೆ ಪಡೆದ ಶಾಲೆಗಳ ಸಮಗ್ರ ದತ್ತಾಂಶ ಸಂಗ್ರಹಣಾ ವ್ಯವಸ್ಥೆ (Ministry of Education / NIEPA). ಪ್ರತಿ ಶಾಲೆಗೆ 11-ಅಂಕಿಯ UDISE+ ಕೋಡ್ — ಶಾಲೆಯ profile, teachers, students, infrastructure, finances ಎಲ್ಲವೂ ಈ ವ್ಯವಸ್ಥೆಗೆ ಸೇರುತ್ತದೆ. PM POSHAN, Samagra Shiksha, RTE infrastructure ಮುಂತಾದ ಯೋಜನೆಗಳ ಲೆಕ್ಕಾಚಾರ/ಅನುದಾನಕ್ಕೆ UDISE+ ದತ್ತಾಂಶವನ್ನು ಬಳಸುವ ಸಾಧ್ಯತೆ ಇದೆ — ಶಾಲೆ ಮಾಡಬೇಕಾದದ್ದು certify + freeze; ಪ್ರಸ್ತುತ ವಿಧಾನವನ್ನು ಸಂಬಂಧಿತ ಇಲಾಖಾ ಪರಿಚಲನೆಯಲ್ಲಿ ಪರಿಶೀಲಿಸಿ.

⚠️ ಮುಖ್ಯ ಸೂಚನೆ: 2026-27 cycle ನ Reference Date — 30 ಸೆಪ್ಟೆಂಬರ್ 2026 (ರಾಷ್ಟ್ರೀಯ). ಕರ್ನಾಟಕ State Project Office ಸಹ data submission ಅನ್ನು ಆ ದಿನಾಂಕಕ್ಕೆ ನಿಗದಿ ಮಾಡಿದೆ. ದಿನಾಂಕ/ಮೆನು ಬದಲಾದರೆ ನಿಮ್ಮ BEO/DDPI ಸೂಚನೆಗಳೇ ಅಂತಿಮ.

🌐 UDISE+ Portal 📊 SDMS (Student Module) Login
✅ Data entry ಮೊದಲು ನಾನು ಏನು check ಮಾಡಬೇಕು?
  1. Reference Date & Freeze date: ಈ ವರ್ಷದ reference date (30 Sep 2026) ಮತ್ತು ನಿಮ್ಮ ಜಿಲ್ಲೆಯ freeze ಅಂತಿಮ ದಿನಾಂಕ — BEO/DDPI ಸೂಚನೆ ಪರಿಶೀಲಿಸಿ.
  2. SATS vs UDISE+ student count: SATS ನಲ್ಲಿರುವ enrollment ಮತ್ತು UDISE+ draft data ಹೊಂದಾಣಿಕೆ — ವ್ಯತ್ಯಾಸ ಇದ್ದರೆ ಮೊದಲೇ ಸರಿಪಡಿಸಿ.
  3. APAAR/consent: ಹೊಸ APAAR entry ಗೆ parental consent record ಇದೆಯೇ?
  4. Teachers' data: APO registered teachers ಸಂಖ್ಯೆ, UDISE+ ನಲ್ಲೂ ಇದೆಯೇ?
  5. ಕಳೆದ ವರ್ಷದ certified data: ಹಿಂದಿನ ವರ್ಷ freeze ಆದ data backup/report ಕೈಯಲ್ಲಿ ಇದೆಯೇ — ಹೋಲಿಕೆಗೆ ಅನುಕೂಲ.

1. ಯಾವ ಮಾಡ್ಯೂಲ್, ಯಾರು?

ಮಾಡ್ಯೂಲ್ಯಾರು ಬಳಸುವುದುಏನು ನಮೂದಿಸುವುದು
School Profile & Facilitiesಮುಖ್ಯ ಶಿಕ್ಷಕ (Principal/HM)ಕಟ್ಟಡ, ತರಗತಿ ಕೊಠಡಿ, ಶೌಚಾಲಯ, ನೀರು, ವಿದ್ಯುತ್, ICT, ಗ್ರಂಥಾಲಯ
SDMS (Student Module)ಡೇಟಾ ಎಂಟ್ರಿ ಆಪರೇಟರ್ವಿದ್ಯಾರ್ಥಿ ದಾಖಲಾತಿ, progression, ಪ್ರವೇಶ, APAAR ID, CWSN
Teacher Moduleಶಾಲೆ / BEOಶಿಕ್ಷಕರ ವಿವರ, ಅರ್ಹತೆ, ನೇಮಕ
UD Moduleಜಿಲ್ಲಾ/ರಾಜ್ಯ ಅಧಿಕಾರಿಗಳುಪರಿಶೀಲನೆ, validation, data lock

1

udiseplus.gov.in open → SDMS Login (ವಿದ್ಯಾರ್ಥಿ module) ಆಯ್ಕೆ.

2

State = ಕರ್ನಾಟಕ ಆಯ್ಕೆ — ತಪ್ಪಿದರೆ login error ಬರುತ್ತದೆ.

3

UDISE code (11 ಅಂಕಿ) username ಆಗಿ; password + captcha ನಮೂದಿಸಿ. Password BEO/DDPI/Block MIS coordinator ಕೊಡುತ್ತಾರೆ.

4

ಮೇಲೆ academic year 2026-27 ಕಾಣುತ್ತಿದೆಯೇ check — ಹಳೆಯ ವರ್ಷ ಕಂಡರೆ view-only mode (ನಮೂದಿಗೆ ಆಗುವುದಿಲ್ಲ).

2A. Teacher Module — ಒಂದು ನೋಟ

ಶಿಕ್ಷಕರ ವಿವರ UDISE+ Teacher module ನಲ್ಲಿ: ಹೆಸರು, ಶೈಕ್ಷಣಿಕ ಅರ್ಹತೆ, ವಿಷಯ, ನೇಮಕ/APO ವಿವರ. ಡೇಟಾ ಆಪರೇಟರ್ ಸಾಮಾನ್ಯವಾಗಿ student module ನಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತಾರೆ; ಶಿಕ್ಷಕರ ವಿವರದಲ್ಲಿನ mismatch (ಹೊಸ ನೇಮಕ, ವರ್ಗಾವಣೆ, ನಿವೃತ್ತಿ) physical staff register ಜೊತೆ ಹೋಲಿಸಿ BEO/ಶಾಲಾ ಮುಖ್ಯಸ್ಥರೊಂದಿಗೆ ಸರಿಪಡಿಸಿ.

3. ಡೇಟಾ ಎಂಟ್ರಿ ಸರಿಯಾದ ಸರಣಿ

✅ ಕ್ರಮ ಹೀಗಿದೆ: Student Progression (ಹಿಂದಿನ ವರ್ಷ) → New Admissions → APAAR ID → CWSN/ವಿವರ → Validate → Certify → Freeze. Progression finalize ಮಾಡದೆ ಹೊಸ ವರ್ಷದ entry ಆಗುವುದಿಲ್ಲ.

✅ ಸೂಚನಾ ವೇಳಾ ಯೋಜನೆ (suggested timeline):

  1. ಸೆ. 1–10: Progression finalize + ಹೊಸ ವಿದ್ಯಾರ್ಥಿ entry.
  2. ಸೆ. 11–20: Validation, error correction, APAAR/consent, CWSN.
  3. ಸೆ. 21–25: ಜಿಲ್ಲಾ-ಒಳ internal deadline (BEO approve stage).
  4. ಸೆ. 26–30: Final certify + freeze (30 ಸೆಪ್ಟೆಂಬರ್ 2026 Reference Date).

ಸೂಚಿತ ಯೋಜನೆ ಮಾತ್ರ — ನಿಮ್ಮ ಜಿಲ್ಲೆ/ಬ್ಲಾಕ್‌ನ internal deadline ಬೇರೆಯಿದ್ದರೆ ಅದನ್ನೇ ಪಾಲಿಸಿ.

4. Student Progression (ಹಿಂದಿನ ವರ್ಷ 2025-26)

1

Student Management → Student Progression open.

2

ಪ್ರತಿ ವಿದ್ಯಾರ್ಥಿಗೆ status: Promoted (ಮುಂದಿನ ತರಗತಿ) / Detained (ಅದೇ ತರಗತಿ) / Left with TC (TC ಸಂಖ್ಯೆ + ದಿನಾಂಕ) / Dropout (ಕಾರಣ ಸಹಿತ).

3

ಪ್ರತಿ ತರಗತಿ ಕೊನೆಯಲ್ಲಿ save + confirm — duplicate counting ತಪ್ಪುತ್ತದೆ.

5. New Admissions (2026-27)

1

Student Management → New Admission → Add New Student.

2

ಹೆಸರು (birth certificate/Aadhaar ಪ್ರಕಾರ), DOB (DD/MM/YYYY), ಲಿಂಗ, admission number, admission date, class & section, category (SC/ST/OBC/EWS/General), Aadhaar, ತಾಯಿಯ ಹೆಸರು, contact.

3

Aadhaar ಇಲ್ಲದಿದ್ದರೆ "Aadhaar Not Available" tick + ಕಾರಣ ನೀಡಿ.

4

100+ ವಿದ್ಯಾರ್ಥಿ ಇದ್ದರೆ Excel bulk upload template ಬಳಸಿ (ಸಮಯ ಉಳಿತಾಯ).

5A. ದೊಡ್ಡ ಸಂಖ್ಯೆ — Excel Bulk Upload

  1. SDMS → Student → Bulk Upload / Import Template ಇಳಿಸಿಕೊಳ್ಳಿ (ಪ್ರಸ್ತುತ template ಇಲಾಖಾ ಸೂಚನೆಯಂತೆ).
  2. ಕಡ್ಡಾಯ ಕಾಲಂ: ಹೆಸರು, DOB, ಲಿಂಗ, ತರಗತಿ/ವಿಭಾಗ, admission number & date, ವರ್ಗ, ತಾಯಿಯ ಹೆಸರು, Aadhaar.
  3. DOB format DD/MM/YYYY ಇರಲಿ — ಬೇರೆ format ದೋಷ ತರುತ್ತದೆ.
  4. Duplicate ಅಥವಾ empty Aadhaar ಸಾಲುಗಳನ್ನು template ನಲ್ಲೇ filter ಮಾಡಿ ತೆಗೆದುಬಿಡಿ.
  5. Upload → Preview/Validate → error list ನೋಡಿ → ಸರಿಪಡಿಸಿ → ಮತ್ತೆ upload.
  6. Final ಆಗಿ ಕಡ್ಡಾಯವಾಗಿ Save/Confirm ಮಾಡಿ — upload ಆದಷ್ಟೇ ಉಳಿಸಿದಂತೆ ಆಗುವುದಿಲ್ಲ.

5B. CWSN — ವಿಶೇಷ ಚೇತನ ಮಕ್ಕಳ (Special Needs) ದತ್ತಾಂಶ

SDMS ನಲ್ಲಿ CWSN (Children With Special Needs) module ಇದೆ: ವಿದ್ಯಾರ್ಥಿ Tag → disability type (ಕಣ್ಣು/ಕಿವಿ/ಮಾತು/ಬುದ್ಧಿಮಾಂದ್ಯತೆ ಮುಂತಾದವು) → severity. ಈ ದತ್ತಾಂಶ Samagra Shiksha special education / resource support ಲೆಕ್ಕಕ್ಕೆ ಆಧಾರ.

  1. ಪ್ರತಿ ತರಗತಿಯ CWSN ವಿದ್ಯಾರ್ಥಿಗಳ ಪಟ್ಟಿ — special educator/ದಾಖಲೆಗಳಿಂದ.
  2. SDMS → CWSN → student Tag → disability type ಆಯ್ಕೆ.
  3. ವೈದ್ಯಕೀಯ/ಮೌಲ್ಯಮಾಪನ ಉಲ್ಲೇಖ ಇದ್ದರೆ ನಮೂದಿಸಿ (ಇಲಾಖಾ ಸೂಚನೆಗನುಸಾರ).
  4. Validation ಮೊದಲು CWSN ಸಂಖ್ಯೆ UDISE+ report ವಿರುದ್ಧ cross-check ಮಾಡಿ.

6. APAAR ID (2026-27 cycle ನಲ್ಲಿ ಪ್ರಮುಖ)

  • ಪ್ರತಿ ವಿದ್ಯಾರ್ಥಿಗೆ 12-ಅಂಕಿಯ APAAR ID (NEP 2020 ಅಡಿ) — SDMS ನಲ್ಲೇ ಸಿಗುತ್ತದೆ; ಹಳೆಯದಿದ್ದರೆ "Verify", ಹೊಸದಾದರೆ "Generate New" (ಇಲಾಖಾ ಸೂಚನಾನುಸಾರ).
  • ಪೋಷಕರ digital consent ಸಾಮಾನ್ಯವಾಗಿ ಕಡ್ಡಾಯ — consent form generate → ಸಹಿ → upload (ಪರಿಚಲನೆ ಪರಿಶೀಲಿಸಿ).
  • Consent pending ಇದ್ದರೆ "Consent Pending" ಆಗಿ ಇಡಬಹುದು, ಆದರೆ freeze ಗಿಂತ ಮೊದಲು ಪೂರ್ಣಗೊಳಿಸಿ.
  • APAAR ID/consent completeness ಕುರಿತ ಪ್ರಸ್ತುತ ನಿಯಮವನ್ನು ಇಲಾಖಾ ಪರಿಚಲನೆ ಹಾಗೂ portal notification ನಲ್ಲಿ ಪರಿಶೀಲಿಸಿ — ಅಪೂರ್ಣ consent freeze ಪ್ರಕ್ರಿಯೆಯ ಮೇಲೆ ಪರಿಣಾಮ ಬೀರುವ ಸಾಧ್ಯತೆ ಇದೆ.

7. Verify → Certify → Freeze

1

Data Validation Report run — ದೋಷಗಳನ್ನು ತಿದ್ದಿ (duplicate Aadhaar, invalid DOB, missing APAAR).

2

Admission register ಜೊತೆ ಒಟ್ಟು ದಾಖಲಾತಿ ಕ್ರಾಸ್-ಚೆಕ್ ಮಾಡಿ.

3

Certify Data → ಮುಖ್ಯಶಿಕ್ಷಕರ approve → Freeze Data (30 ಸೆಪ್ಟೆಂಬರ್ 2026 ಒಳಗೆ).

4

Freeze ನಂತರ: ದೋಷ → Request for Change module ನಲ್ಲಿ,DEO formal approval ಇಲ್ಲದೆ ಯಾವುದೇ change ಆಗುವುದಿಲ್ಲ. ಮಧ್ಯದಲ್ಲಿ ಸೇರುವ ವಿದ್ಯಾರ್ಥಿ → Mid-Year Admission module (ನವೆಂಬರ್ ಮುಂದಿನ period).

✏️ Practical example — SATS vs UDISE+ count check: ನಿಮ್ಮ ಶಾಲೆಯ SATS ನಲ್ಲಿ 245 ವಿದ್ಯಾರ್ಥಿಗಳು, ಆದರೆ UDISE+ draft data ನಲ್ಲಿ 241 ಕಾಣಿಸುತ್ತಿದೆ ಎಂದುಕೊಳ್ಳಿ.

  1. ಮೊದಲು class-wise/taragiTI-wise ಅಂತರ ಗುರುತಿಸಿ — ಯಾವ ತರಗತಿಯಲ್ಲಿ 4 ವಿದ್ಯಾರ್ಥಿಗಳ ವ್ಯತ್ಯಾಸ?
  2. ಆ ತರಗತಿಯ SATS ಪಟ್ಟಿ vs UDISE+ admission register ಜೊತೆ ಹೋಲಿಸಿ — ಯಾವವರ ಹೆಸರು UDISE+ ನಲ್ಲಿ ಕಾಣೆಯಾಗಿದೆ?
  3. ಕಾಣೆಯಾದವರು: ಹೊಸ ಪ್ರವೇಶ? transfer-in? TC-out ಆದವರನ್ನು ಅಮೂಲಾಗ್ರ UDISE+ ಎಣಿಕೆಯಲ್ಲಿ ತೆಗೆಯಬೇಕಿತ್ತೇ?
  4. Progression/New Admission entry ಸರಿಯಿದೆಯೇ ತಿದ್ದಿ, validation run ಆಗಿ count ಹೊಂದಾಣಿಕೆಯಾಗುವವರೆಗೆ repeat.

ಹೀಗೆ SATS, admission register ಮತ್ತು UDISE+ — ಮೂರು source ಒಂದೇ count ಗೆ ಬಂದಾಗ certify ಮಾಡುವುದು ಸುರಕ್ಷಿತ. Count mismatch ಇರುವಾಗ freeze ಮಾಡಬಾರದು.

8. Freeze/Submit ಮೊದಲು — Final Checklist ✅

✅ Submit/freeze ಒತ್ತುವ ಮೊದಲು ಈ 10 ಅಂಶಗಳನ್ನು ಪರಿಶೀಲಿಸಿ:

  • 1. SATS, UDISE+ ಮತ್ತು admission register — ಮೂರರಲ್ಲೂ student count ಹೊಂದಿದೆಯೇ?
  • 2. Class-wise/taragiTI-wise enrollment ವಿವರ register ಜೊತೆ match ಆಗಿದೆಯೇ?
  • 3. Progression (ಹಿಂದಿನ ವರ್ಷ) complete ಮತ್ತು confirm ಆಗಿದೆಯೇ?
  • 4. ಹೊಸ admissions ಎಲ್ಲರಿಗೂ ಹೆಸರು/DOB birth certificate ಪ್ರಕಾರ ಇದೆಯೇ?
  • 5. APAAR ID generate/verify + ಉಳಿದ consent ಪೂರ್ಣವಾಗಿದೆಯೇ?
  • 6. CWSN/tagging vendor list ಜೊತೆ ಹೊಂದಿದೆಯೇ?
  • 7. Validation report ನಲ್ಲಿ ದೋಷ (error) ಶೂನ್ಯ; ಇದ್ದರೆ ತಿದ್ದಿದ್ದೀರಾ?
  • 8. Teachers' module ಹೊಸ ನೇಮಕ/ವರ್ಗಾವಣೆ/ನಿವೃತ್ತಿ ಸರಿಪಡಿಸಿದ್ದೀರಾ?
  • 9. Final preview PDF/ವರದಿ load ಆಗಿ data ಸರಿಯಾಗಿ ಕಾಣುತ್ತಿದೆಯೇ?
  • 10. Reference date (30 Sep 2026) ಒಳಗೆ submit ಆಗುತ್ತಿದೆಯಾಗಿದೆಯೇ — ಕೊನೆ ದಿನ ಬಿಡದೆ ಒಂದು ವಾರ ಮುಂಚಿತ?

9. ಡೇಟಾ ಎಂಟ್ರಿಯಲ್ಲಿ ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು

⚠️ ಈ ತಪ್ಪುಗಳನ್ನು ತಪ್ಪಿಸಿ:

  • ತಪ್ಪು 1 — Progression finalize ಮಾಡದೆ ಹೊಸ ವರ್ಷ entry: ಹಿಂದಿನ ವರ್ಷ complete ಮಾಡದಿದ್ದರೆ portal block ಮಾಡುತ್ತದೆ — ಮೊದಲು Progression.
  • ತಪ್ಪು 2 — DOB format ಬೇರೆ (mm/dd/yyyy): ಸ್ಥಿರವಾಗಿ DD/MM/YYYY — Excel template ನಲ್ಲಿ ಕಾಲಂ format check.
  • ತಪ್ಪು 3 — Duplicate Aadhaar/duplicate student: Bulk upload ಮೊದಲು Aadhaar duplicate filter; registration ನಲ್ಲಿ ಒಂದೇ ಮಗು ಎರಡು ಬಾರಿ ಬೇಡ.
  • ತಪ್ಪು 4 — Save ಮಾಡದೆ ಸೆಷನ್ ಬಿಡುವುದು: ದೊಡ್ಡ ಪಟ್ಟಿಯಲ್ಲಿ ಮಧ್ಯೆ ಮಧ್ಯೆ save ಮಾಡಿ; logout/login session expire check.
  • ತಪ್ಪು 5 — ಹೆಸರು/ಜಾತಿ ದಾಖಲೆ ನೋಡದೆ ನಮೂದಿಸುವುದು: ಬೇರೆ ಬೇರೆ ಕ್ಷೇತ್ರದಲ್ಲಿ ಭಿನ್ನ ಹೆಸರು — birth certificate/Aadhaar ಹೊಂದಾಣಿಕೆ ಇರಲಿ.
  • ತಪ್ಪು 6 — Validation warning ಅನ್ನು ನಿರ್ಲಕ್ಷಿಸುವುದು: Warning/model answer ಕೂಡ mismatch ಸೂಚಿಸಬಹುದು — cross-check ಮಾಡಿ; ಖಚಿತವಾದಾಗ ಮಾತ್ರ proceed.

11. ಪ್ರಮುಖ ಅಂಶಗಳು ⭐

  • Freeze missed = ಅನುದಾನಕ್ಕೆ ಬಾಧಕ: PM POSHAN, Samagra Shiksha, RTE infrastructure ಅನುದಾನ ಲೆಕ್ಕಕ್ಕೆ ಶಾಲೆ certify+freeze ಮಾಡದಿದ್ದರೆ ಆ cycle ಗೆ ಪರಿಣಾಮ ಬೀರಬಹುದು (ಇಲಾಖಾ ಪರಿಚಲನೆ ಪರಿಶೀಲಿಸಿ).
  • Keep records open: ನೋಂದಣಿ register, TC register, staff details — ಡೇಟಾ ಎಂಟ್ರಿ ಮಾಡುವಾಗ physically open ಇರಲಿ; "ಆಮೇಲೆ ಸರಿಪಡಿಸುತ್ತೇನೆ" ಬೇಡ.
  • ಒಬ್ಬ ಮುಖ್ಯ: ಒಬ್ಬರು enter, ಇನ್ನೊಬ್ಬರು cross-check — 10 ನಿಮಿಷ review.
  • ಕೊನೇ ದಿನ ಬೇಡ: portal traffic spike — ವೇಳಾಪಟ್ಟಿಗಿಂತ ಒಂದು ವಾರ ಮುಂಚಿತವೇ submit.
  • Reports save: preview PDF, reports, verification screenshot — ಒಂದು folder ನಲ್ಲಿ ದಾಖಲಿಸಿ.

12. FAQ — ಪದೇ ಪದೇ ಕೇಳಲಾಗುವ ಪ್ರಶ್ನೆಗಳು

1. UDISE code ಸಿಗುತ್ತಿಲ್ಲ — ಎಲ್ಲಿಂದ ತರುವುದು?

ಹಿಂದಿನ ವರ್ಷದ UDISE report ನಲ್ಲಿ, recognition certificate ನಲ್ಲಿ, ಅಥವಾ BEO/DDPI office ನಿಂದ. 11-ಅಂಕಿಯ code ಕರ್ನಾಟಕದ್ದು "29" ಆರಂಭ. ಹಳೆಯ report/dashboard ನಲ್ಲೂ code ಕಾಣುತ್ತದೆ — ನೋಡಿದ್ದರೂ ಸಿಗದಿದ್ದರೆ BEO/Block MIS ಕೇಳಿ.

2. ಹಳೆಯ ವರ್ಷದ ದತ್ತಾಂಶ lock ಆಗಿದೆ — ಸರಿಪಡಿಸಲು ಹೊಸ ವರ್ಷದ entry ಆಗುತ್ತದೆಯೇ?

ಹಳೆಯ ವರ್ಷ complete ಆದಾಗ ಮಾತ್ರ ಹೊಸ ವರ್ಷದ entry ಆಗುತ್ತದೆ. Lock ಆಗಿದ್ದರೆ block/district MIS ನಿಂದ unlock/change request. ಪೂರ್ವವರ್ಷದ data ಇನ್ನು open ಇದ್ದರೆ ಮೊದಲು ಅದನ್ನು ಮುಗಿಸಿ — ನಂತರವೇ 2026-27. "ಆಮೇಲೆ ಸರಿಪಡಿಸುತ್ತೇನೆ" ಎಂಬ ಉದ್ದೇಶ ಬೇಡ; free ಆಗಿರುವಾಗಲೇ complete ಮಾಡಿ.

3. APAAR ID ಮಾಡಲು ಒಂದು student ನ consent ಬರುವುದಿಲ್ಲ — freeze ಆಗುತ್ತದೆಯೇ?

"Consent Pending" ಆಗಿ enter ಮಾಡಬಹುದು, ಆದರೆ freeze ಮೊದಲು consent + APAAR ಪೂರ್ಣಗೊಳಿಸುವಂತೆ ಇಲಾಖೆ ನಿರೀಕ್ಷಿಸುತ್ತದೆ — ಪೋಷಕರಿಗೆ ಬೇಗ ತಿಳಿಸಿ, form ಸಹಿ/ಅಪ್‌ಲೋಡ್ ಮುಗಿಸಿ. Consent ಬರದ ಕಾರಣದಿಂದ ಪೂರ್ಣ ಮುಗಿಸಲು ಸಾಧ್ಯವಾಗದಿದ್ದರೆ BEO/ಜಿಲ್ಲಾ MIS ನಿಂದ ಪ್ರಸ್ತುತ guidance ಪಡೆಯಿರಿ.

4. November ನಲ್ಲಿ ಹೊಸ ವಿದ್ಯಾರ್ಥಿ ಸೇರಿದರೆ ಏನು?

Freeze ನಂತರ Mid-Year Admission module ಮೂಲಕ — ಮುಖ್ಯ baseline ಗೆ ಸೇರದೆ supplementary ನಲ್ಲಿ ಬರುತ್ತದೆ, ಮುಂದಿನ ವರ್ಷದ ದಾಖಲೆಗೆ. Reference date ಆದಮೇಲೆ ಸೇರಿದ ಮಗುವಿಗೆ UDISE+ main count ನಲ್ಲಿ ಬದಲಾವಣೆ ಬೇಡ — module ನ ಸೂಚನೆಗಳನ್ನು ಪಾಲಿಸಿ.

5. Error "invalid" ಎನ್ನುತ್ತಿದೆ — ಯಾರನ್ನು ಕೇಳುವುದು?

Block MIS coordinator / BRC ಮೊದಲನೆಯ; ಆಗದಿದ್ದರೆ ಜಿಲ್ಲಾ (DDPI) MIS; ರಾಷ್ಟ್ರೀಯ helpdesk ಹಂತಕ್ಕೆ udiseplus@nic.in / 011-24305493 (ಸಂಪರ್ಕ ವಿವರ ಬದಲಾಗಬಹುದು — udiseplus.gov.in ನಲ್ಲಿ ಖಚಿತಪಡಿಸಿ). Error message ನ screenshot ಇಟ್ಟುಕೊಳ್ಳಿ — ಸಹಾಯ ಕೇಳಲು ವೇಗ.

6. ಹೊಸ ಶಿಕ್ಷಕರನ್ನು UDISE+ ನಲ್ಲಿ ಸೇರಿಸಲು ಏನು ಬೇಕು?

Teacher module ನಲ್ಲಿ ಹೆಸರು, ಶೈಕ್ಷಣಿಕ ಅರ್ಹತೆ, ವಿಷಯ, ನೇಮಕ/APO ವಿವರ ನಮೂದಿಸಿ. ಹೊಸ ನೇಮಕದ ದಾಖಲೆ (appointment order) physical staff register ಜೊತೆ ಹೊಂದಿಕೆಯಾಗಲಿ. mismatch ಇದ್ದರೆ school ಹೆಡ್/BEO ಜೊತೆ ಸರಿಪಡಿಸಿ — validation warning ಕಾಣಿಸಬಹುದು.

7. Reference date ಮತ್ತು Freeze date ಒಂದೇಯೇ?

ಸಾಮಾನ್ಯವಾಗಿ Reference Date (ಡೇಟಾ ಯಾವ ದಿನಾಂಕದ ಸ್ಥಿತಿಯಲ್ಲಿ) ಮತ್ತು Freeze/submission deadline (ಆ ದತ್ತಾಂಶ lock ಮಾಡುವ ದಿನ) ಹತ್ತಿರ ಇರುತ್ತದೆ ಆದರೆ ಒಂದೇ ಆಗಿರಬೇಕಿಲ್ಲ. ನಿಮ್ಮ ಜಿಲ್ಲೆಯ freeze date BEO/DDPI ಸೂಚನೆಯಲ್ಲಿ ಕೊಡುಗೆ ಇದೆ — ಅದನ್ನು ಪಾಲಿಸಿ. ರಾಷ್ಟ್ರೀಯ Reference Date 2026-27: 30 Sep 2026.

8. GIS/ಫೋಟೋ ಕ್ಯಾಪ್ಚರ್ UDISE+ freeze ಒಳಗೇ ಇದೆಯೇ?

GIS capture (ಶಾಲಾ ಜಿಯೋ-ಟ್ಯಾಗಿಂಗ್/ಫೋಟೋ) ವೇಳಾಪಟ್ಟಿ ಪ್ರತಿ ವರ್ಷ ಇಲಾಖಾ ಸೂಚನೆಯಂತೆ ಬರುತ್ತದೆ — freeze ದಿನಾಂಕಕ್ಕೆ ಮೊದಲೇ/ನಂತರ ಎಂದು ನಿಗದಿಯಾಗಬಹುದು. ವಿವರಕ್ಕೆ UDISE+ GIS ಕ್ಯಾಪ್ಚರ್ ಮಾರ್ಗದರ್ಶಿ ಮತ್ತು ನಿಮ್ಮ BEO ಸೂಚನೆ ನೋಡಿ.

9. ಒಂದೇ Aadhaar ಎರಡು ವಿದ್ಯಾರ್ಥಿಗಳಿಗೆ ನಮೂದಾಗಿದೆ — ಹೇಗೆ?

Validation report duplicate Aadhaar ತೋರಿಸುತ್ತದೆ — register ಪರಿಶೀಲಿಸಿ ಯಾರು ಸರಿ ಎಂದು ನೋಡಿ, ತಪ್ಪು Aadhaar correct/remove ಮಾಡಿ. ಸಿಬ್ಬಂದಿ ಸಂಬಂಧವಿಲ್ಲದಿದ್ದರೆ (ಉದಾ. twins share) ಇಲಾಖಾ ಸೂಚನೆಯಂತೆ ಪ್ರತಿ ವಿದ್ಯಾರ್ಥಿಗೆ ಪ್ರತ್ಯೇಕ Aadhaar ದಾಖಲಿಸಿ.

10. certify ಮಾಡಿದರೆ freeze ಆಗುವುದೇ — ಅಥವಾ ಪ್ರತ್ಯೇಕ step ಆ?

ಸಾಮಾನ್ಯವಾಗಿ Certify ಒಂದು step, Freeze ಇನ್ನೊಂದು step — certify ಮಾಡಿದ ಕೂಡಲೇ freeze ಆಗಬೇಕಿಲ್ಲ. ವೇಳಾಪಟ್ಟಿ/ಇಲಾಖಾ ಸೂಚನೆಯಂತೆ ಎರಡೂ ಪೂರ್ಣ ಮಾಡಿ. ಮುಖ್ಯಶಿಕ್ಷಕರ approve ಮಾಡದಿದ್ದರೆ freeze ಆಗದೇ ಇರಬಹುದು — role/approval ಸರಿಯಾಗಿದೆಯೇ ನೋಡಿ.
